# 一键安装说明

## 一句话

在**你自己的电脑**上跑一条命令，VPS 上的备份系统就装好了：

```bash
bash deploy.sh root@你的服务器
```

端口不是 22 时，写成 `root@你的服务器:2222`：

```bash
bash deploy.sh root@1.2.3.4:2222
```

---

## 为什么在你的电脑上跑，而不是在 VPS 上跑

因为**只有你这边有浏览器**。Google Drive 授权必须点一次登录，这件事没法在纯命令行的 VPS 上完成。

`deploy.sh` 把这一步提前到你本机做完，然后把拿到的令牌随包一起传上去。整个过程中你只需要在浏览器里点一次「允许」。

它一共做四件事：

| 步骤 | 做什么 |
|---|---|
| 1 | 检查 ssh 能不能连上目标机 |
| 2 | 本机做 Google Drive 授权（没装 rclone 就临时下一份，不动系统） |
| 3 | 把 `install.sh` + `backup-v2.sh` 打包传上去 |
| 4 | 在 VPS 上跑安装向导，装完把令牌文件抹掉 |

> 想在 VPS 上直接装也行：把 `install.sh` 和 `backup-v2.sh` 传到同一个目录，`bash install.sh`。  
> 区别是授权环节会提示你「去有浏览器的电脑上跑 `rclone authorize`，把输出的 JSON 粘回来」——多一点手工。

## 安装向导会问你什么

一路回车就是推荐值。

| 问题 | 默认 | 说明 |
|---|---|---|
| 备份哪些目录 | 自动探测 | 空格分隔。只放**不可再生**的东西：配置、上传文件、证书。代码和依赖不要放，那些从 git 和镜像仓库恢复 |
| 数据库类型 | 自动探测 | `none` / `mysql` / `docker-mysql` |
| 加密口令 | 自动生成 48 位 | **回车就用随机串，然后立刻存进密码管理器** |
| 本地保留天数 | 7 | 省磁盘，够应急回滚就行 |
| 云端保留天数 | 90 | 这才是保命的那份 |
| rclone remote 名 | `gdrive` | |
| 网盘里的目录 | `backup/<主机名>` | |
| 通知方式 | `notion` | `none` / `notion` / `webhook` |
| 每天几点跑 | `03:00` | 按 VPS 的时区 |

## 装完自动做哪些检查

安装脚本最后会自己验一遍，**红字和叹号都是真问题，不是装饰**：

- 配置能加载、关键项不为空
- **用你这份口令做一次加密→解密往返**——口令打错的话，这里就会红
- **磁盘空间预检**：加密后还要再写一份同样大的文件，所以按源数据的 2.2 倍算，不够就报警
- 备份目录没有套在备份源里面（否则会无限自我复制，撑爆磁盘）
- Google Drive 真的能连上
- 往 Notion / 上报服务**真发一条测试记录**，看能不能写进去
- 定时任务真的排上了

## 验证它真的在工作

```bash
# 立刻跑一次，看完整过程
ssh -t root@你的服务器 'systemctl start backup-v2.service && journalctl -u backup-v2 -n 50'

# 看下次什么时候跑
ssh root@你的服务器 'systemctl list-timers backup-v2.timer'

# 看日志
ssh root@你的服务器 'tail -50 /opt/backups/backup.log'
```

跑完后去 Notion 表格里看，应该出现一行记录。**表格里那一行的「上传」列写着「成功」才算真的备份成功**——只写「成功」不带上传状态的通知，是没法证伪的通知。

## 出问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `连不上 root@...` | 密钥 / 端口 / 防火墙 | 先手工 `ssh root@...` 确认能进 |
| 授权页没弹出来 | 浏览器没被调起 | 终端里会打印一个 `http://127.0.0.1:53682/auth?...` 地址，手动打开 |
| 授权完没解析到令牌 | rclone 输出格式变了 | 脚本会打印原始输出，把 JSON 那段手工粘到 VPS 的提示里 |
| 装完提示「读不到网盘根目录」 | 令牌失效 / Drive API 没开 | `ssh root@... 'rclone lsd gdrive:'` 手工复查 |
| `Failed to setup mount namespacing`（systemd） | 数据目录不存在 | 安装时已 `mkdir -p` 建好；还报就手工建一遍 `/var/lib/backup-v2` 与 `/opt/backups` |
| Notion 写入失败 | 最常见：**数据库没「连接」给 integration** | 在 Notion 页面点 `···` → 连接 → 选你那个 integration。90% 的人卡在这 |
| 想改配置 | | 改 `/etc/backup.env`，下一次跑就生效，不用重启 |

## 卸载

```bash
ssh -t root@你的服务器 'bash /root/wb-backup/install.sh --uninstall'
```

会停掉定时任务、删掉脚本。**配置、历史备份、网盘授权都会保留**——里面的加密口令删了就再也解不开网盘上的数据了，所以卸载脚本故意不碰它们，要清干净得你自己动手（命令它会打印出来）。

---

## 两个提醒

**加密口令必须在 VPS 之外另存一份。** 它只躺在 `/etc/backup.env` 里，机器丢了就是「备份还在，但永远打不开」。

**先小规模试。** 把备份目录指向一个小目录跑一轮，确认邮件/Notion 能收到、能解密，再放开真正的数据。

## 文件清单

| 文件 | 作用 |
|---|---|
| `deploy.sh` | 在你的电脑上跑，一键部署到 VPS |
| `install.sh` | 在 VPS 上跑的安装向导（`deploy.sh` 会自动调用它） |
| `backup-v2.sh` | 备份主脚本，被安装到 `/usr/local/bin/` |
| `test-install.sh` | 端到端演练：`bash test-install.sh` 可在本机（macOS 也能跑）完整验证一遍 |
| `backup.env.example` | 配置模板，手工改配置时对照用 |
| `notify-notion-setup.md` | Notion 接入的界面操作步骤与排错表 |
